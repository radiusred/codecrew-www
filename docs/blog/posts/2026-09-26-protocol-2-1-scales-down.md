CodeCrew shipped [v2.1.0](https://github.com/radiusred/gh-codecrew/releases/tag/v2.1.0) on 24 September, and with it protocol 2.1 — the first minor since [2.0 moved everything under `.codecrew/`](2026-09-07-protocol-2-0-and-the-migration.md). A minor is a promise about what does not happen: [the changelog](https://github.com/radiusred/gh-codecrew/blob/main/CHANGELOG.md) says "2.1 is additive: every pointer, layout and recorded comment 2.0 accepted stays valid", and a 2.0 pointer is current under it with nothing to migrate.

The changes came from the fleet. [The milestone that built them](https://github.com/radiusred/gh-codecrew/issues/353) opens on projects running 2.0 outside the hub — a solo blog among them — that "reported ceremony that was the same size whatever the change". Four such reports, with appraisals written on them, became the design notes: [housekeeping](https://github.com/radiusred/gh-codecrew/issues/343), [a requirement dropped mid-milestone](https://github.com/radiusred/gh-codecrew/issues/348), [a three-line milestone paying a full record](https://github.com/radiusred/gh-codecrew/issues/349), and [a contract that assumed every hub is a product repository](https://github.com/radiusred/gh-codecrew/issues/350).

## What 2.1 adds

**A requirement can be struck.** Under 2.0, [a requirement withdrawn by decision](https://github.com/radiusred/gh-codecrew/issues/348) had no word that `milestone close` would accept — nothing was built, so every verdict was either false or blocking. Now [the spec](https://github.com/radiusred/gh-codecrew/blob/main/SPEC.md#milestone) lets it be struck: a `**Decision:**` naming the ID comes first, then [`gh codecrew milestone strike`](https://github.com/radiusred/gh-codecrew/blob/main/CLI.md#gh-codecrew-milestone-strike) posts `**M1-R2 — struck.**` with a link to it on the milestone issue. The body is never edited; a strikethrough in it means nothing. The verb refuses `DECISION_UNRECORDED` without a real Decision behind the link, `milestone close` counts a struck requirement as terminal, and `--reinstate` undoes it the same way it was made. Striking is a scope change, so it belongs to the coordination layer rather than QA — in the spec's words, "the human, a human and an agent jointly, or an agent the human has deliberately put in charge of coordination." It does not have to be a person. Awkwardly for a launch post, the milestone that shipped the verb struck nothing: [its record](https://github.com/radiusred/gh-codecrew/blob/main/docs/milestones/18-the-protocol-scales-down.md) notes that `milestone strike` "was not used live".

**Housekeeping gets a light path.** Until now [every change went](https://github.com/radiusred/gh-codecrew/issues/343) milestone, task, plan, PR, review, verdict, record. [SPEC §4](https://github.com/radiusred/gh-codecrew/blob/main/SPEC.md#housekeeping) now carves out changes with no decision in them, and the test is mechanical rather than a matter of size: "a tool states the target, and the diff is the whole decision". A contract sync, a bot's dependency bump or a formatter's fix travels as a `chore:` commit naming the tool, one pull request, the review the reviewer seat's routing requires, and a rebase merge by its author — no task, plan or verdict. A hand-spotted typo does not qualify, because no tool defined it. The fence has one gate: the milestone record, whose target the protocol states and whose content is Decisions already on the trail. [The M18 record](https://github.com/radiusred/gh-codecrew/pull/376) was the first to take that path. This post is not housekeeping — it is full of choices — so it has [a task](https://github.com/radiusred/codecrew-www/issues/66).

**`roles sync` brings contracts up to date.** [The new verb](https://github.com/radiusred/gh-codecrew/blob/main/CLI.md#gh-codecrew-roles-sync) writes the embedded role contracts, and `.codecrew/AGENTS.md` in a hub or a spoke, wherever the local file is absent or still an earlier release's unedited text, as one local commit that is never pushed. Anything else is the project's fork, and the verb refuses `CONTRACT_FORKED` or `AGENTS_FORKED` before writing a byte. [`status`](https://github.com/radiusred/gh-codecrew/blob/main/CLI.md#gh-codecrew-status) now reports a missing contract as well as a drifted one, and names which of the two verbs applies.

**Agents check their CLI before their first verb.** The CLI compares protocol majors only, so a binary a minor behind its hub runs quietly and fails later. The scaffolded `.codecrew/AGENTS.md` therefore opens with a version check — [the hub's own](https://github.com/radiusred/gh-codecrew/blob/main/.codecrew/AGENTS.md) makes it step 2: compare the protocol `gh codecrew version` prints with the hub pointer's `codecrew:` field, then upgrade or raise it with the human, "Never upgrade mid-task." Why there, and not in the release notes? [The Decision that added it](https://github.com/radiusred/gh-codecrew/issues/353#issuecomment-5819250070) gives the operator's reason: "the CHANGELOG reaches neither an operator who skips it nor a coordinating agent, which has no obligation to read it — the check has to be in the text every dispatched agent loads." A [second Decision](https://github.com/radiusred/gh-codecrew/issues/353#issuecomment-5819365327) made `roles sync` the delivery route, so existing projects receive the check without anyone editing files by hand.

## What an adopter runs

From [the changelog's 2.1.0 entry](https://github.com/radiusred/gh-codecrew/blob/main/CHANGELOG.md):

> What an operator does: upgrade every seat's binary — every machine and orchestrator that runs the verbs — with `gh extension upgrade codecrew`, before running `roles sync` anywhere; then run `gh codecrew status` in each repository and, where it reports a contract or the agents file missing or at an earlier release's text, run `gh codecrew roles sync` and deliver its commit as a housekeeping pull request, which is how an existing project receives the version check.

A hand-written `.codecrew/AGENTS.md` is refused rather than overwritten; the hub's own is one, so there `roles sync` is run by naming the roles.

## Bedding in

2.1 now gets lived on before anything else moves. [The milestone for this post](https://github.com/radiusred/gh-codecrew/issues/384) restates the rule: "no verb changes its arguments, output, writes or refusal codes, and SPEC.md is untouched." Meanwhile, what the fleet notices is filed as captures. Two came from the first record on the light path: its contract [names no branch and does not say whether the changelog gets an entry](https://github.com/radiusred/gh-codecrew/issues/377), and [`milestone close` no longer surfaces the record's raw material](https://github.com/radiusred/gh-codecrew/issues/379), so the Decisions for M18's record were gathered by hand — by me. They will wait their turn, which is rather the point.
